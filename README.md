# 収納量調査 回答収集アプリ（GitHub Pages + GAS API 構成）

フロントを GitHub Pages に置き、データの読み書きだけを Apps Script のAPIに投げる構成です。
GASウェブアプリ直結に比べて、上部の警告バーが出ず、初回表示も速くなります。

**案件ごとにスプレッドシートを分けられます。** スクリプトとPagesは1組だけ用意し、
案件マスタで接続先を切り替えます。

| 置き場 | 中身 |
|---|---|
| GitHub Pages | `index.html`（回答画面・管理画面） |
| Apps Script | `gas-code.gs`（API） |
| マスターのスプレッドシート | `案件`（キー／案件名／シートID）と `マスター設定`（あいことば） |
| 案件ごとのスプレッドシート | 設定／②什器サイズ／部門マスタ／提出／回答ログ／採用／①回答 |

## 1. Apps Script 側

1. Googleドライブで**マスター用**のスプレッドシートを作る（例：`収納量調査_マスター`）。
   ここには案件の一覧だけが入り、回答データは入りません
2. **拡張機能 > Apps Script**
3. `コード.gs` の中身を全部消して `gas-code.gs` を貼り付け、保存
   - **`index.html` は不要です。**以前の構成で作っていた場合は削除してください
4. 関数選択を **`setup`** に切り替えて **実行**
   - **`doGet` のままだと何も起きません**
   - 権限の承認は「詳細」→「（プロジェクト名）に移動」→「許可」
   - 完了ダイアログは**スプレッドシートのタブ側**に出ます。エディタで待っていても進みません
5. 「マスター設定」シートの**管理用あいことば**を確認する（初期値 `STORART2026`）
6. **デプロイ > 新しいデプロイ > ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
7. 発行された `.../exec` のURLをコピー

このURLをブラウザで直接開くと「回答収集API」という文字だけが出ます。それが正常です。

## 2. GitHub Pages 側

### スクリプトで一括デプロイ

`index.html` と同じフォルダで実行します。GitHub CLI（`gh`）が入っていれば、
リポジトリの作成とPagesの有効化まで自動で進みます。

**Windows（PowerShell）**

```powershell
.\deploy.ps1 -ApiUrl "https://script.google.com/macros/s/AKfycb.../exec" -Repo "storage-survey"
```

**mac / Linux / Git Bash**

```bash
chmod +x deploy.sh
./deploy.sh -u "https://script.google.com/macros/s/AKfycb.../exec" -r storage-survey
```

2回目以降は更新だけなので、引数なしで実行できます。
API_URL は一度書き込めば保持され、変更したいときだけ渡し直します。

### 手動でやる場合

1. `index.html` の**先頭にある1行**に、さきほどの `/exec` URLを貼る

```js
var API_URL = "https://script.google.com/macros/s/AKfycb.../exec";
```

2. リポジトリに置いて Pages を有効化
3. Pages のURLに `?admin=1` を付けて開く

URLを入れずに開くと、モックデータで画面だけ動く確認モードになります。
保存はされないので、レイアウト確認用と思ってください。

## 3. 案件を登録する

Pages のURLに **`?admin=1`**（案件キーなし）を付けて開くと、**案件の管理画面**になります。

1. 案件ごとに新しいスプレッドシートを作る（例：`A社_収納量調査`）
2. 管理画面の「案件を追加・更新する」に入力
   - **キー** … 半角英数字。URLに入ります（例 `honsha2026`）
   - **案件名** … 表示用
   - **スプレッドシートID / URL** … アドレスバーのURLをそのまま貼ってOK。IDを取り出します
3. 「登録する」を押すと、そのスプレッドシートにデータ用の6シートが自動で作られます
4. カードに出る**回答用URL**を配ります

同じキーで登録し直すと上書きされます。「一覧から外す」を押しても、
スプレッドシートと回答データは消えません。

## 4. 画面

| | URL |
|---|---|
| 案件の管理 | `https://<ユーザー名>.github.io/<リポジトリ>/?admin=1` |
| 回答画面 | `.../?p=<案件キー>` |
| 案件ごとの管理 | `.../?p=<案件キー>&admin=1` |

管理画面は**マスター設定の「管理用あいことば」1つ**で保護されています（初期値 `STORART2026`）。
案件ごとには分かれていません。変更するときは「マスター設定」シートの値を直接書き換えてください。

## 通信の仕組み

- 読み取りは **JSONP**（`?callback=`）
- 書き込みは **POST**（`Content-Type: text/plain` にしてプリフライトを避ける）。
  失敗した場合はJSONPに自動で落ちます

GASは他オリジンからの通常の `fetch` を受けにくいため、この2本立てにしています。

## シート

### 案件ごとのスプレッドシート

| シート | 役割 |
|---|---|
| 設定 | 案件名・選択肢 |
| ②什器サイズ | 収納番号・寸法・什器仕様・段数・部門の初期値 |
| 部門マスタ | 部門／課／出力先(G\|H) |
| 提出 | 提出ID・部門・課・回答者・状態 |
| 回答ログ | 1行＝1提出×1収納×1段。**これが正のデータ** |
| 採用 | 重複したときにどの提出を採るか |
| ①回答 | 集計ツール用。管理画面から生成される（生成物なので直接編集しない） |

### ②什器サイズ

| 収納番号 | 什器幅(mm) | FM | 什器奥行(mm) | 什器高さ(mm) | 什器仕様 | 段数 | 部門 |
|---|---|---|---|---|---|---|---|
| A001 | 900 | 0.9 | 450 | 2100 | 6段キャビネット | | 総務部 |

- **収納番号** は `A001` 形式。ゼロ埋めは自動で揃えます
- **段数** は空欄でよく、什器仕様の「6段」から読みます。全角「６段」も可。
  什器仕様に段数が書けない場合だけ段数列を使ってください
- 段数が読み取れない什器は**一覧に出ません**。管理画面で一覧表示されます
- **部門** は任意

### 部門マスタ

| 部門 | 課 | 出力先 |
|---|---|---|
| 人事部 | ES企画課 | |
| | 人事労務課 | |
| 総務部 | 総務課 | H |

2行目以降の部門は空欄で構いません（結合セル対応）。出力先は空欄なら G。

## 回答者の流れ

1. 配布された `?p=…` 付きのURLを開き、**自分の部門と課を選んで「回答をはじめる」**。氏名は任意
2. 収納番号を選び、1段ずつ「保存して次の段へ」
3. 全段終わったら「入力完了」
4. 担当ぶんが終わったら **「提出する」**

- **各段の「使用している部門・課」には、最初に選んだ所属が自動で入ります。**
  自分の部署の収納なら、段ごとに触るのは「収納物はありますか？」だけです
- 所属と提出IDは端末に覚えるので、2回目からは所属の画面は出ません
- **別の端末に変えると新しい提出になります**
- 「収納物はあるが、自分の部署以外の物品である」を選んだ段は「他部署待ち」になります
- 他の人が登録した収納には「（他の人が登録済み）」と表示されます。**止めはしません**
- **入力途中の収納が残っていると提出できません**
- 提出後は編集不可。「提出を取り消す」で戻せます

## 管理画面

### 設定の確認

- **この案件の回答用URL** … そのままコピーして配れます
- **②什器サイズ** … 段数の内訳、読み取れない什器、収納番号の重複
- **部門マスタ** … 結合セルをどう畳んだか、出力先
- **選択肢** … 現場に出る選択肢の中身
- **貼り付けで入れ替え** … ExcelからコピーしてSheetを丸ごと差し替え
- **キャッシュを消して読み直す** … シートを直接編集した内容を即反映

### 突き合わせ

- **提出状況** … 回答者ごとの件数・状態。「差し戻す」で編集可能に戻す
- **重複** … 同じ収納を複数人が登録した場合。内容の一致／不一致を判定し、採用する回答を選べる
- **不足** … 誰も登録していない収納／段が埋まっていない収納
- **他部署待ちの段** … その部署への依頼が必要なもの
- **①回答シートを作る** … 採用回答を1行にまとめる。作成後
  「ファイル > ダウンロード > Microsoft Excel」で保存して集計ツールへ

## ①回答の列構成（全68列）

```
A  タイムスタンプ
B  回答者
C  収納番号
D  収納番号の頭にあるアルファベットを選択してください
E  収納番号を選択してください
F〜 段ごとに9列 × 7段
    n段目を使用している部門
    n段目を使用している課
    上からn段目に収納物はありますか？
    n段目の収納で過半数を占めているものは何ですか？
    n段目の収納物に関して、今後、執務環境の見直しを行う場合に、どの程度整理・移動が可能ですか？
    n段目の今後使用するタイミングを教えてください。
    n段目の保管が必要な理由を教えてください。
    n段目の残す50%の、今後使用するタイミングを教えてください。
    n段目の残す50%の、保管が必要な理由を教えてください。
```

旧フォームの E〜H（什器単位の部門・課）は廃止し、部門は段ごとに持ちます。
見出しの表記ゆれ（全角「１段目」、Googleフォーム由来の連番サフィックス）も全廃しています。
**集計ツールはこの列構成に合わせた改修が必要です。**

存在しない段は `段数+1` 段目に「◯段目以降は存在しない」を入れ、それ以降は空欄。

## 動作を軽くするための作り

- 設定・②什器サイズ・部門マスタは**10分間キャッシュ**。起動のたびにシートを読み直しません
- **自分の回答は起動時にまとめて受け取ります。**収納を開くときに通信しません
- **段の保存では進捗を返しません。**進捗は画面側で計算します

## 注意点

- **1つのスクリプトが複数のスプレッドシートを開きます。**案件のスプレッドシートは、
  スクリプトの所有者（＝デプロイした人）がアクセスできる必要があります
- **API_URL は公開されます。** Pages に置く以上、ソースを見れば誰でも分かります。
  もともと「アクセスできるユーザー：全員」の公開エンドポイントなので前提は変わりませんが、
  リポジトリを公開にする場合はその点を理解のうえで運用してください
- **回答ログが正**です。`①回答` は生成物なので、直接編集しても次の作成で消えます
- 集めきったら **デプロイを管理 > アーカイブ** でAPIを止めてください
- コードを直したあとは **デプロイ > デプロイを管理 > 編集（鉛筆）> バージョン「新バージョン」> デプロイ**。
  この手順ならURLは変わりません
